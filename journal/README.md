# Optimization journal

This branch (`optimization-journal`) is the working record of the project.
`main` holds the final result only; everything here explains how it got there.

| Path | What it is |
|---|---|
| `METHOD.md` | The loop every optimization went through, and the rules for accepting one |
| `TIMELINE.md` | What happened in which order: decisions, findings, dead ends |
| `experiments/<suite>.jsonl` | One line per optimization attempt: idea, change, before, after, verdict |
| `EXPERIMENTS.md` | The same attempts as tables (generated by `tools/journal.py`) |
| `PROGRESS.md` | How the headline numbers moved from commit to commit (generated) |
| `reports/` | The write-ups of each line of work, as delivered |

The commit history of this branch is part of the record: work-in-progress
snapshots are committed as they were, including states that were later
replaced. `results/*.json` at each commit are the measurements of that state.

## Format of an experiment line

```json
{"id": "hqc-03", "date": "2026-11-11", "suite": "hqc", "target": "hqc1/decaps",
 "idea": "why this should help", "change": "what was changed, in which files",
 "metric": "avg_us", "before": 1117700, "after": 27850,
 "checked": "kat+fingerprint", "verdict": "kept", "note": "anything a reader must know"}
```

`verdict` is `kept`, `rejected` (measured, no gain or a regression),
`partial` (kept in part) or `superseded` (replaced by a later attempt).
`checked` says how correctness was established for the changed code.
`before` and `after` are measured on the ESP32-C3 unless `note` says otherwise.
